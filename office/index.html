📦 Office LTSC 2024 安装指南

下载 → 生成配置 → 安装批量版 → KMS 激活
⚠️ 动手之前，先看这两件事
① 直接双击 setup.exe 装出来的是「零售版」，不能 KMS 激活
微软官方镜像 ProPlus2024Retail.img 里的 setup.exe 如果直接双击运行，默认按镜像自带的零售配置安装，装完是零售 / Microsoft 365 授权模式， 用 ospp.vbs 换 GVLK 也激活不了。
要装批量授权版（LTSC Volume），必须自己写一份 Configuration.xml， 指定产品 ProPlus2024Volume + 通道 PerpetualVL2024， 再用命令行调用：setup.exe /configure Configuration.xml。
② 装了批量版，还是要 KMS
配置文件里的 PIDKEY 只是把 GVLK（通用批量授权密钥）预置进去，它本身不是激活码。 GVLK 的作用是告诉 Office「去找 KMS 服务器要授权」，所以 安装完仍然需要 KMS 激活，有效期 180 天、到期自动续。
真正能脱离 KMS 的只有 MAK 密钥（要花钱买）或零售密钥——那就不是本页的路子了。
🧭 两种装法，先选一种

方案 A：离线镜像安装省流量

  • 下载 2GB 的官方 .img 镜像
  • 双击挂载成一个虚拟光驱（盘符不固定）
  • 用镜像里的 setup.exe + 自己的 XML 安装
  • 装完的是批量版，源文件来自本地，不再下载
  • 坑：盘符每台机器都不一样，见下方第 4 步

方案 B：ODT 在线安装最稳

  • 下载微软官方部署工具 ODT（约 10MB）
  • 解压得到 setup.exe
  • 直接 setup.exe /configure xxx.xml
  • 安装过程中从微软 CDN 拉取 PerpetualVL2024 的源文件
  • 不涉及盘符问题，但要边下边装（约 2GB 流量）
选哪个？
网络还行就用 方案 B，微软官方文档推荐的就是这条路，不会有版本对不上的问题； 要装多台机器、或者已经把 2GB 镜像下好了，就用 方案 A。 下面第 3 步的生成器两种都支持，第 4 步给的一键脚本会自动判断用哪种。
1
卸载电脑里已有的 Office

新机器预装的 Microsoft 365、零售版 Office 2024、或者以前的 Office 2016/2019，都会和批量版冲突，装之前先清干净。

  • 1图形界面：设置 → 应用 → 已安装的应用，找到 Microsoft Office / Microsoft 365 卸载。
  • 2卸不干净：用微软官方的支持和恢复助手（SaRA）Office 卸载工具，能清残留。
  • 3命令行：用下面这个卸载配置，配合 setup.exe 一条命令清掉所有点击运行版 Office。

用法：管理员命令行里执行 setup.exe /configure Remove-Office.xml。 注意 <RemoveMSI /> 只能卸载 2016 及更早的 MSI 版，2019 以后的点击运行版要用这里的 <Remove All="TRUE"/>。

4
执行安装（盘符的坑在这里解决）
为什么不能把 SourcePath="E:" 直接抄给别人
E: 是你这台机器挂载镜像时恰好分到的盘符。别人电脑上可能是 F:、G:， 也可能 E: 正好是个 U 盘。SourcePath 指错路径，安装就会报「找不到安装源 / 30015」之类的错。
三种解法，任选其一（推荐第一种）：
  • 1用一键 .bat：脚本开头会遍历 A~Z 盘，找同时存在 setup.exe 和 Office\Data 的那个盘，找到后把真实盘符写进临时 XML 再安装。换任何机器都不用改。
  • 2干脆不写 SourcePath：把 XML 复制到挂载出来的光驱根目录（和 setup.exe 同级），然后在那个目录下执行 setup.exe /configure Configuration.xml。setup 会默认在自己所在目录找源文件。
  • 3解压到固定目录：用 7-Zip 把 .img 解压到 D:\Office2024，XML 里写 SourcePath="D:\Office2024"。路径自己定，就不会漂了。
手动执行的话，管理员命令行里这么敲：
:: 1) 先切到挂载出来的盘（盘符换成你自己的） E: :: 2) 用你的配置文件安装（XML 路径按实际填） setup.exe /configure "%USERPROFILE%\Downloads\Configuration.xml" :: 方案 B（ODT 在线装）则是切到 ODT 解压出来的目录 setup.exe /configure Configuration.xml
参数是 /configure，不是 /config
点击运行版（Click-to-Run）的 setup.exe 官方参数是 /configure、/download、/packager。 /config 是老 MSI 版 Office 的写法，敲错了大概率直接弹安装界面走默认零售配置——又白装一次。

安装窗口关掉不代表失败：选了静默安装时界面全程不显示，命令行返回提示符才算跑完，一般 5~15 分钟。

5
KMS 激活

装完打开 Word → 文件 → 账户，产品信息里应该写着 Microsoft Office LTSC 专业增强版 2024， 状态多半是「需要激活」。这时候把它指向 KMS 服务器就行：

:: 进入 Office 安装目录 cd /d "%ProgramFiles%\Microsoft Office\Office16" :: 指定 KMS 服务器 cscript ospp.vbs /sethst:kms.0xc.in :: 激活 cscript ospp.vbs /act :: 查看激活状态（看到 LICENSE STATUS: ---LICENSED--- 就成了） cscript ospp.vbs /dstatus
不用 /inpkey 了
第 3 步的配置里已经预置了 GVLK，装完密钥就在里面，直接 sethst + act 即可。 如果你当时没勾「预置 GVLK 密钥」，那就先执行 cscript ospp.vbs /inpkey:XJ2XN-FW8RK-P4HMP-DKDBV-GCVGB 再激活。

❓ 常见问题 / 踩坑记录
装了批量版是不是就不用 KMS 了？▼
还是要。批量版预置的是 GVLK，它的唯一用途就是让 Office 去找 KMS 主机换授权，本身不含授权。 装完不激活会一路提示「产品未激活」，功能逐步受限。
真正不需要 KMS 的只有两种：买 MAK 密钥（企业批量授权，联网向微软激活一次即可），或者买零售版密钥（那就不该装 Volume 版）。
我照着别人的 XML 写了 SourcePath="e:"，报错怎么办▼
因为 e: 只是那个人挂载镜像时分到的盘符。检查思路：
  1. 打开「此电脑」，看挂载出来的 Office 光驱到底是哪个盘符；
  2. 确认那个盘根目录下同时有 setup.exe 和 Office\Data 文件夹；
  3. 把 XML 里的盘符改成实际的，或者干脆删掉 SourcePath 属性，然后在光驱根目录下运行 setup.exe；
  4. 最省事的做法是直接用本页第 3 步生成的一键 .bat，它自己扫盘。
另外注意 SourcePath 要指向 包含 Office 文件夹的那一层，不要把 \Office 或 \Office\Data 写进去。
报错 30015 / 30088 / 提示找不到安装文件▼
基本都是「本地源里没有配置要的那份文件」。按顺序排查：
  • SourcePath 路径对不对（见上一条）；
  • 位数对不对：镜像是 64 位的，XML 里写 OfficeClientEdition="32" 就会找不到文件；
  • 语言对不对：简体中文镜像里只有 zh-cn，配置里写 en-us 或 MatchOS 匹配到别的语言就会缺文件；
  • 把 AllowCdnFallback="TRUE" 打开（本页生成器默认就是开的），缺什么让它自己去微软 CDN 补；
  • 还是不行就换方案 B，用 ODT 全程在线装，最干净。
零售镜像真的能装批量版吗？▼
镜像里的源文件（Office\Data 下那几个 .cab / .dat）是各版本共用的，授权模式由配置里的 Product ID 和 Channel 决定，所以绝大多数情况下用零售镜像当离线源装 PerpetualVL2024 是没问题的，这也是社区最常见的玩法。
但要说清楚：这不是微软文档里写的标准路径。官方推荐用 ODT 直接从 CDN 装批量版。 如果镜像的版本号和批量通道对不上，就会出现上一条里的缺文件报错——这种时候别死磕，直接换方案 B。
为什么我的 ExcludeApp Publisher 没生效▼
因为 Office LTSC 2024 本来就不含 Publisher 了（微软已宣布 Publisher 在 2026 年 10 月后不再支持）。 写 <ExcludeApp ID="Publisher" /> 不会报错，但也没有任何作用，可以删掉。 同理，2024 的 Skype for Business 默认就不装，要装反而得去 OCT 里手动打开。
SharedComputerLicensing / SCLCacheOverride 这些要写吗▼
不用。这几个属性是给 Microsoft 365 的共享计算机激活（远程桌面多用户场景）用的， 微软文档明确写了 对 Office LTSC 2024 不适用。网上流传的配置里经常带着它们，属于无害但多余，删掉更清爽。 DeviceBasedLicensing 同理。
AUTOACTIVATE=1 为什么没自动激活▼
AUTOACTIVATE="1" 是让 Office 安装完自己去激活，但它找 KMS 主机靠的是域内 DNS 的 _vlmcs._tcp SRV 记录。家用网络 / 非域环境下根本查不到这条记录，自然激活不了， 有时还会拖慢安装收尾。所以本页默认不勾它，装完手动 ospp.vbs /sethst 指定服务器更快更可控。
装完还是显示「Microsoft 365」或者零售版▼
说明这次安装没按你的 XML 走，常见原因：
  • 双击了 setup.exe 而不是用命令行带 /configure；
  • 参数写成了 /config；
  • XML 路径有空格没加引号，setup 没读到文件，退回默认配置；
  • 机器上还残留着旧的点击运行版，新安装被当成「加装语言/组件」合并进去了——先按第 1 步卸干净。
确认方法：Word → 文件 → 账户，产品名必须是「Office LTSC 专业增强版 2024」，更新通道显示 PerpetualVL2024。
一键 .bat 双击没反应 / 一闪而过▼
脚本需要管理员权限，请右键 → 以管理员身份运行。 如果提示「没有找到 Office 安装源」，说明镜像没挂载成功，或者解压出来的目录里缺 Office\Data； 这种情况把 ODT 的 setup.exe 和这个 .bat 放同一个文件夹，脚本会自动改走在线安装。
